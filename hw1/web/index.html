Project 1

Images of the Russian Empire

Colorizing the Prokudin-Gorskii Photo Collection

Background

The images in this project come from Sergei Mikhailovich Prokudin-Gorskii's photographs of the Russian Empire. In 1907, when color photography was the wave of the future, he captured color images by photographing the same scene three times through separate blue, green, and red filters and recording the negatives on a single glass plate.

The digitized images do not initially look like normal color photographs. Each scan contains three vertically stacked grayscale images, corresponding to the blue, green, and red channels in that order, but each layer contains obvious color fringes around objects and edges and doesnt look alined.

In this project, my goal is to separate these three images, align them spatially, and stack them together to reconstruct a single RGB color image.

Step 1: The Brute Force Approach

Motivation Behind Exhaustive Search

I first implemented a simple single-scale alignment algorithm using exhaustive search. The idea is straightforward: if the correct displacement is somewhere within a small range, we can simply test every possible (x, y) translation and select the one that produces the best match.

For example, with a search range of [-15, 15], there are $31*31=961$ possible translations for each channel. For each candidate translation, I shifted one channel and calculated an image similarity score against the reference channel. I used the blue channel as the reference and aligned the green and red channels to it.

L2 Distance

The first metric I tried was the L2 (Euclidian) distance. For two images img1 and img2, the L2 error is $L_2(I_1,I_2) = \sqrt{ \sum_{x,y} (I_1(x,y)-I_2(x,y))^2 }$. We are interested in the displacement that minimizes this value as best alignment. If two channels are correctly aligned, corresponding pixels should have similar intensity values, resulting in a smaller overall difference.

In my implementation, I used the squared version of the L2 distance to simplify calculation:

score = np.sum((shifted - im2) ** 2)

Normalized Cross-Correlation

To metigate the brightness issue, I also implemented Normalized Cross-Correlation (NCC). Instead of directly comparing raw pixel values, NCC first subtracts the mean from each image and normalizes the resulting vectors: $\hat{I}_1 = \frac{I_1-\mu_1} {\|I_1-\mu_1\|}$ and $\hat{I}_2 = \frac{I_2-\mu_2} {\|I_2-\mu_2\|}$.

The NCC score is then their dot product: $NCC(I_1,I_2) = \hat{I}_1 \cdot \hat{I}_2$

Unlike L2 distance, where smaller is better, we want to maximize the NCC score for better alignment. By subtracting each image's mean, NCC approach focuses more on whether the patterns and structures in the images line up rather than requiring their absolute intensities to be the same.

Comparing L2 and NCC

I tested both metrics on the low-resolution JPEG images. In general, both metrics were able to find good translations for images where the channels had relatively similar intensity patterns. However, NCC was more appropriate for cases where the same objects had noticeably different brightness across channels.

Debugging the Alignment

One important debugging issue was how to handle pixels that move outside the image boundaries.

My first approach used np.roll to shift the image. However, np.roll wraps pixels around the opposite side of the image. For example, pixels shifted off the left side reappear on the right side. These wrapped pixels are not actually part of the corresponding image region, so including them in the similarity calculation can produce incorrect scores.

To fix this, my NCC implementation explicitly computes the overlapping regions of the two images for every candidate displacement. For a positive or negative dx or dy, I create corresponding slices so that only pixels that genuinely overlap are compared.

For example, instead of comparing the entire shifted image, the algorithm effectively compares: $I_1[\text{overlap}] \quad\text{with}\quad I_2[\text{corresponding overlap}]$.

After finding the best displacement, I use np.roll to apply the final translation to the original image. Since the rolled image contains artificial wrap-around pixels, I then crop a margin from the borders before stacking the three channels.

Step 2: Optimization — Faster Alignment for Bigger Images

Why Brute Force Becomes Too Slow

Although exhaustive search works well on small JPEG images, it becomes much more expensive for the high-resolution TIFF images. The alignment looks way more blurred and you can immediately tell three colors separately.

This problem is caused because the number of pixels increases dramatically with image resolution. At the same time, the required displacement can also be much larger than the [-15, 15] pixel window that works well for the smaller images.

To optimize this, I used image pyramid to make the search more efficient.

Multi-Scale Image Pyramid

I implemented a multi-scale image pyramid that repeatedly downsamples the image by a factor of two. For example, with four levels: $I_0 \rightarrow I_1 \rightarrow I_2 \rightarrow I_3$ where each subsequent level is approximately half the width and height of the previous level.

I built the pyramid using sk.transform.rescale with anti-aliasing:

smaller = sk.transform.rescale(
pyramid[-1],
0.5,
anti_aliasing=True
)

The anti-aliasing step helps prevent artifacts when reducing the image resolution.

Coarse-to-Fine Alignment

Rather than beginning the search at full resolution, I start at the smallest image in the pyramid. At this coarse resolution, a large displacement in the original image corresponds to a much smaller displacement. Therefore, a relatively small search window can cover a much larger effective region of the original image.

IOnce the best displacement is found at the coarse level, I move to the next larger image. Before searching again, I multiply the current displacement by two because the image dimensions double between pyramid levels, so the estimated displacement must also be scaled accordingly.

if level < levels - 1:
dx *= 2
dy *= 2

The major advantage of this approach is that we do not need to search a huge displacement range at full resolution. We can find the approximate alignment using a small search window and then refine it as we move back to the original resolution.

Final Alignment

After running pyramid alignment separately for the green and red channels, I obtained final displacement vectors:

FINAL Green offset: (dx, dy) FINAL Red offset: (dx, dy)

These offsets were then applied to the original-resolution channels. I cropped the borders affected by the shifting and combined the channels using im_out, which is implemented as following:

im_out = np.dstack([
r_aligned,
g_aligned,
b_cropped
])

The resulting image reconstructs the original scene as a single RGB photograph.
